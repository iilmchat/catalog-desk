# CD-ADR-006. Восстановление качества данных на сервере

**Статус:** Accepted (проект V15) · **Дата:** 2026-11-24

## Контекст

Тестовый detail-экспорт Перекрёстка (PLU 24139) показал:
`composition = null` при полном составе в `details_text`; БЖУ сдвинуты на одну
метку; `description` пуст при наличии текста описания. V14 уже чинит БЖУ на
сервере, но не чинит состав и описание, а detail-файлы с чужим SAP вообще
не доходят до импорта (CD-002).

## Решение

Импорт и миграция обязаны восстанавливать отсутствующие поля из
`details_text` единым серверным парсером:
- состав — до следующей метки (`Вес`, `Срок хранения`, …) без требования `\n`;
- описание — между `Описание` и `Показать полностью`/`Состав`;
- БЖУ — уже существующая функция `parse_nutrition_from_details_text()`.

Индикатор заполненности считает «сведения найдены в любом источнике».
В `details_text` сохраняется исходный текст; каждая починка — через
новую миграцию с флагом в `catalog_ui_meta`.

## Последствия

+ Полнота карточки перестаёт зависеть от капризов DOM-парсера клиента.
+ Один и тот же код работает для обеих сетей (одинаковые русские метки).
+ Основа для проверки противоречий и «статуса источника».
− Восстановление — эвристика; результат помечается как «анализ текста»,
  не лабораторная проверка.
