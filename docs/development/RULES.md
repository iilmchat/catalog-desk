# Правила разработки Catalog Desk

**Версия:** 0.1
**Обновлено:** 2026-11-24
**Назначение:** единый свод правил для разработчика и ассистента.

---

## 1. Базовые правила

| # | Правило |
|---|---|
| 1.1 | Комментарии и docstring — на русском; идентификаторы — английские |
| 1.2 | Имена таблиц и колонок — нейтральные, без названия магазина |
| 1.3 | Антибот-проверки **не обходятся**: CAPTCHA → останов и ручное продолжение |
| 1.4 | Все времена — UTC ISO-8601; `captured_at` (снимок) отдельно от `imported_at` (загрузка) |
| 1.5 | Идемпотентность: повтор того же `source_hash` ничего не меняет |
| 1.6 | Источник каждой записи обязателен: `chain`, `sap_code`, `source_url`, `source_hash`, `collection_mode` |
| 1.7 | Никаких обращений к внутренним API магазинов и чтения cookies в сборщиках |
| 1.8 | Новый магазин = запись в конфиге + адаптер, а не копия проекта и не замена `35XY` |
| 1.9 | Внешние данные принимаются только через JSON-файлы с проверкой `source` |
| 1.10 | Проблемы фиксируются как `CD-XXX` в [KNOWN_ISSUES.md](../KNOWN_ISSUES.md) |

## 2. Документация (в том же коммите, что и код)

| # | Правило |
|---|---|
| 2.1 | `CHANGELOG.md` (Keep a Changelog) обновляется вместе с кодом, не задним числом |
| 2.2 | Рабочая секция — `[Unreleased]`; при релизе → `[V15.0] — YYYY-MM-DD` |
| 2.3 | `README.md` — при изменении запуска, CLI, API или требований |
| 2.4 | Изменение модели данных → обновить `ARCHITECTURE.md` и дизайн `v15/` |
| 2.5 | Отчёт по шагу — по шаблону [reports/README.md](reports/README.md) |
| 2.6 | Секреты и персональные данные — никогда в git |

## 3. Рабочий процесс

| # | Правило |
|---|---|
| 3.1 | Один шаг TODO = один коммит |
| 3.2 | Перед коммитом — `git status --short` |
| 3.3 | Формат commit: `<type>(<scope>): <subject>`; типы `feat`, `fix`, `docs`, `test`, `chore`, `refactor` |
| 3.4 | Ссылка на `CD-XXX` в subjects/commit body обязательна, если правка из реестра |
| 3.5 | Тесты зелёные до коммита и после push |
| 3.6 | Force-push — только `--force-with-lease` |
| 3.7 | Временные отладочные скрипты после задачи удаляются |
| 3.8 | Перед миграцией/импортом в рабочую базу — копия файла базы |

## 4. Технические правила

| # | Правило | Причина |
|---|---|---|
| 4.1 | Цены хранятся как `REAL` в текущей схеме; сравнение/расчёты — на границеikipedia приложения; новая схема может перейти на копейки | совместимость с V9 |
| 4.2 | Новые ключи таблиц включают `chain`; старые `(sap_code, plu)` сохраняются как часть ключа | 110 совпадающих PLU |
| 4.3 | Миграции аддитивные и идемпотентные (`_add_column_if_missing`, `IF NOT EXISTS`) | база V14 не пересоздаётся |
| 4.4 | Модификация снимков деталей — только через новую миграцию с флагом в `catalog_ui_meta` | одноразовые чистки V14 |
| 4.5 | Регексы русскоязычных меток БЖУ/состава не дублируются: один парсер на сервере + тонкий клиентский слой | в V14 уже есть рассинхронизация |
| 4.6 | `source`-маркеры и префиксы файлов — из конфига сети | CD-010 |
| 4.7 | userscript-доступ к локальному API — только `127.0.0.1` / `localhost`, `@connect` явно перечислен | безопасность |
| 4.8 | Загрузка фото — только с хостов из конфига, Referer соответствует сети | CD-013 |
| 4.9 | Тесты не обращаются к сайтам; фикстуры — реальные экспорты с личными данными вырезаны | стабильность |
| 4.10 | Изменение интерфейса HTTP API → обновить `README.md` и QA-чеклист | docs as code |

## 5. Git

| # | Правило |
|---|---|
| 5.1 | `.gitignore`: `*.sqlite3*`, `*.xlsx`, `*.csv`, `5ka_exports/`, `5ka_product_details/`, `photos5ka/`, `__pycache__/`, `.venv/`, `.env`, `*.zip` |
| 5.2 | `.gitattributes`: текстовые файлы — `eol=lf`, `.bat` — `eol=crlf`, изображения — binary |
| 5.3 | `.editorconfig`: UTF-8, 4 пробела для Python, 2 для JS/HTML/CSS |
| 5.4 | До первого коммита проверить `git config user.name/email` |
| 5.5 | `.env` и ключи не коммитятся; при утечке — смена секрета, затем `filter-repo` |
