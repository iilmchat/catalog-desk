## 1. Переключатель сети

В шапке вместо «АКТИВНЫЙ МАГАЗИН SAP 35XY»:

```
Сеть: [ Пятёрочка ▾ ]   Магазин: [ 35XY ▾ ]   V15.0
```

`chain` хранится в `localStorage` и передается в каждом запросе;
`GET /api/dashboard|analytics|products|changes|enrichment/*?chain=…`.
При отсутствии `chain` сервер использует `5ka` (обратная совместимость).

## 2. Экраны

| Раздел | Изменение |
| :--- | :--- |
| Обзор | KPI в контексте сети; кнопка «Все сети» для сводки |
| Каталог | фильтр по сети, колонка «Сеть», поиск по PLU |
| Аналитика | график цены по сети, сравнение дат, топы роста/падения |
| Качество | индикатор заполненности, источник поля, «все сети» / «текущая сеть» |
| Очередь обновления | задачи с `chain`; «Повторно загрузить карточку» открывает нужный домен |
| Массовое обогащение | выбор сети, отдельный прогресс и CAPTCHA-статус на сеть |
| Сравнение | 2–5 товаров, цена за кг/100 г, БЖУ, состав, лучшие значения |
| Сбор и импорты | загрузка JSON обеих сетей, журнал с `source` и `chain` |

## 3. HTTP API (внутренний)

Существующие роуты остаются, но принимают `chain`. Ответы API добавляют
поле `chain` в каждой строке. Новые публичные роуты — в S22:

| Метод | URL | Назначение |
| :--- | :--- | :--- |
| `GET` | `/api/v1/stores` | список сетей и магазинов |
| `GET` | `/api/v1/products?chain=&q=&category=&page=` | каталог |
| `GET` | `/api/v1/products/{chain}/{plu}` | карточка |
| `GET` | `/api/v1/prices?chain=&plu=&from=&to=` | история цен |
| `GET` | `/api/v1/compare?chain_a=&chain_b=&plu=` | сравнение сетей |
| `POST` | `/api/v1/imports` | импорт (идемпотентность по `source_hash`) |

Формат ошибки: `{"success": false, "error": {"code", "message"}}`.
Сервер по-прежнему слушает только `127.0.0.1`.

## 4. Не делать

- Не создавать `ui_v15` как копию `ui_v14` с заменёнными строками: это приведёт
  к расхождению версий (в проекте уже v10…v14).
- Не хранить брендинг в JS-коде: цвета и подписи — из конфига сети.
- Не показывать данные двух сетей в одной таблице без явной колонки «Сеть».
