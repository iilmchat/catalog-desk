# Changelog

Все значимые изменения проекта фиксируются в этом файле.
Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [Semantic Versioning](https://semver.org/lang/ru/).

## [Unreleased]

### Added
- Browser-like DOM regression harness на captured HTML fixtures обеих сетей: проверка userscript payload, изоляции product-screen, секций description/composition, скрытых блоков и исключения рекомендаций/отзывов. Harness запускается в CI.

### Fixed
- Извлечение описания Пятёрочки останавливается на следующей секции карточки, а не только на кнопке «Показать полностью»; состав извлекается только из самостоятельной подписи секции.
- Перекрёсток не принимает скрытый `[data-qa="product-description"]` за видимое описание; парсеры обеих сетей используют построчные границы состава без ASCII `\b`.

### Changed
- Сверена документация V17/S23 с фактическим состоянием `main` после merge PR #8: V17 отмечен завершённым, решение о dedicated-column SQLite migration явно отложено, статусы CD-024/CD-025 и покрытие обеих сетей уточнены.
- Проведён аудит PR #7: изменения пересекаются с актуальными userscript из PR #8; предложенный текстовый поиск описания Перекрёстка не переносится из-за риска захвата скрытого/SEO-текста. PR #7 не используется как источник для merge; его тестовый DOM stub заменяется полноценным DOM harness в S23.

### Added
- Сокращённые DOM regression-фикстуры, сформированные по переданным HTML-снимкам обеих сетей: Перекрёсток PLU 4414429 и Пятёрочка PLU 4275044; добавлены Python-тесты `product-screen`, breadcrumbs, цены, фото, состава и характеристик.
- Для userscript Пятёрочки добавлено ограничение сбора узлом `[data-qa="product-screen"]`; рекомендации и внешняя разметка страницы не попадают в текст карточки. Из видимого блока «Описание» извлекается фактическое описание.

### Changed
- Таксономия Перекрёстка учитывает реальную категорию «Для Нового года» как `non_food`.
- На сохранённой странице Пятёрочки доступна только цепочка «Главная / Каталог / товар» без явной категории. Классификация остаётся `unknown`; заголовок «Агар ... пищевой» намеренно не используется как доказательство класса.

### Verified
- DOM-тесты подтверждают для ёлочки: цена 1399.99 RUB, фото, состав «Полиэтилен, джут.», вес 0.37 кг, бренд Маркет, страна Китай и атрибут «Срок хранения: не ограничен».
- DOM-тесты подтверждают для агара: цена 134.99 RUB, фото, БЖУ 0.4 / 0.0 / 0.0 и 174.0 ккал, описание, состав, вес 0.007 кг, срок 365 дней, условия хранения и бренд Dr. Bakers.

### Added
- Базовая модель качества каталога V17: классы food / pet_food / non_food / unknown, применимость атрибутов отдельно от результата извлечения и расчёт полноты по обязательным применимым полям.
- Для непродовольственных карточек общий блок «Состав» направляется в материалы, а не в пищевые ингредиенты; неизвестная классификация сохраняет текст для проверки.
- Документирована политика: `docs/PRODUCT_DATA_QUALITY.md`; добавлены unit- и integration-тесты для пищевых, непродовольственных и неизвестных товаров.
- Карточка товара показывает полноту применимых данных, класс товара, материалы и статус «БЖУ не применимо» для non-food.

### Changed
- Userscripts Перекрёстка и Пятёрочки определяют класс по breadcrumbs / категории, не по одному названию; передают applicability и семантический тип состава. Для Пятёрочки добавлены Cyrillic-safe границы парсинга БЖУ и состава. Парсер состава Перекрёстка также использует границы целых подписей, чтобы не обрезать слова вроде «древесина» по подстроке «вес».
- Импорт одиночных и пакетных detail JSON сохраняет метаданные в зарезервированном `attributes_json._catalog_meta`, не требуя миграции SQLite.
- Поиск пищевых ингредиентов и сахара ограничен подтверждёнными food / pet_food; материалы non-food и неразмеченные legacy-составы не интерпретируются как ингредиенты.


### Added
- Реальная DOM-фикстура карточки Перекрёстка PLU 4406119 и regression tests для названия, бренда, цены, изображений, БЖУ, атрибутов, отсутствующего состава и исключения рекомендаций.
- Node.js regression test helper-функций userscript Перекрёстка; тест запускается в GitHub Actions.

### Fixed
- Парсер БЖУ Перекрёстка: заменены ASCII-ориентированные границы слова `\\b`, которые не распознавали русские подписи после чисел и сдвигали значения; добавлен тест на фактический порядок текста DOM.

### Changed
- Userscript Перекрёстка предпочитает `[data-qa="product-screen"]` как корень товара; рекомендации и карусели за пределами этого узла не попадают в `details_text` и поиск изображений.
- Атрибуты карточки извлекаются из повторяющихся `[data-qa="product-detail-attribute"]`; скрытая SEO meta description не используется как фактическое описание товара.

### Verified
- Сохранённая карточка Перекрёстка содержит название, бренд, цену 369.99 RUB, три image nodes, nutrition (52.7 kcal, proteins 1.2 g, fats 0.3 g, carbs 11.2 g) и 11 характеристик.
- В HTML-фикстуре отсутствуют состав и отдельное фактическое описание; SEO meta description повторяет маркетинговый заголовок и намеренно не считается описанием.

### Remaining
- CD-024 частично подтверждён: состав/описание не представлены в этой карточке; для полного закрытия нужны фикстуры страниц, где эти секции реально доступны/свёрнуты.
- CD-025 частично реализован для Перекрёстка; требуется DOM-покрытие Пятёрочки и интеграционная проверка формирования payload.

### Verified
- После релиза V16.1.0 проверено одиночное обновление одной карточки Пятёрочки (PLU 4275044, SAP 35XY) и одной карточки Перекрёстка (PLU 4406119, SAP XSEO): запись деталей и снимка истории созданы; массовые очереди и batch-state не затронуты.
- Локальная регрессия перед этой проверкой: 100 Python-тестов прошли; синтаксис четырёх userscript проверен Node.js; SHA-256 рабочей SQLite-базы до/после тестов совпал.

### Known limitations
- Проверка одной карточки Перекрёстка выявила, что `description` сейчас отправляется как `null`; `composition` не извлечён из проверенной страницы, а `details_text` требует более строгого отсечения блоков отзывов/рекомендаций. См. CD-024.
- Автотесты userscript пока проверяют синтаксис и статические маркеры, но не воспроизводят DOM карточек; см. CD-025.

## [V16.1.0] — 2026-11-26

### Added
- В массовой очереди показывается распределение карточек по полноте: 100%, 80%, 60%, 40%, 20% и 0%.
- Карточку товара можно открыть нажатием на её строку или название в массовой очереди.

### Changed
- Сводные показатели «Обработано», «Ожидают» и общий прогресс рассчитываются по фактическому наличию записи в `product_details`; статусы действий очереди остаются отдельными.

## [V16.0.0] — 2026-11-26

### Added
- Одиночное обновление сведений из карточки товара по одноразовому токену, привязанному к `chain + SAP + PLU`.
- Отдельный импорт одного снимка в `product_details`, историю деталей, журнал импортов и галерею; массовая очередь и batch-состояние не меняются.
- Userscript V16 для обеих сетей: одиночный режим и прежний пакетный режим с чтением только видимого DOM.

### Fixed
- Прогресс категорий рассчитывается по наличию записи `product_details`, а не по статусу задачи массовой очереди.
- Файлы одиночных снимков хранятся в подпапке `_single_refresh`, не попадающей в общий импорт JSON.

## [V15.1.0] — 2026-11-25

### Fixed
- Основной импорт отклоняет неверный SAP, смешанные сети и URL, принадлежащий другой сети.
- Userscript Перекрёстка адресует batch status/fail явно к `chain=perekrestok`; состояние пакетной обработки разделено по сетям.
- Существующее пакетное состояние V14 переносится в новую таблицу без потери текущей карточки.
- Миграция V9→V10 сохраняет составной внешний ключ `(chain, sap_code, plu)` и проверяет `PRAGMA foreign_key_check`.

### Changed
- Планировщик обозначен как реестр ручных DOM-выгрузок; он не запускает браузер или сбор автоматически.
- Добавлены тесты изоляции очередей, валидации SAP/доменов и внешних ключей.
- Добавлен GitHub Actions CI для Python-тестов и синтаксиса userscript.

### Added
- (записи добавляются в каждом коммите с кодом)

## [V15.0] — 2026-11-25

**Тема:** Catalog Desk становится многомагазинной системой: Пятёрочка + Перекрёсток в одной базе с историей, качеством данных и локальным API.

### Added
- Документация по образцу PriceScope: `README.md`, `GET_STARTED.md`, `TODO.md`,
  `docs/` (хаб, реестр `CD-XXX`, TODO_KI, TODO_SPRINTS, RULES, ARCHITECTURE,
  RELEASES, ADR, дизайн V15, пользовательское руководство и QA-чеклист).
- Git-репозиторий: `.gitignore`, `.gitattributes`, `.editorconfig` — код и документация
  версионируются, база/выгрузки/фотографии исключены.
- S15: `catalog_config.py` — реестр сетей `5ka`/`perekrestok` (домены, префиксы URL,
  хосты фото, SAP, `source`-маркеры, пути); `catalog_migrations.py` — миграция V9→V10
  с добавлением `chain`, расширением ключей и одноразовым бэкапом; 6 новых тестов
  (`test_catalog_config_v15.py`).

### Added
- S16: контракт Export v2 (`schema_version=2`, `chain`) с чтением v1; сеть определяется
  по явному полю, затем по домену URL, затем по маркеру `source`; `--chain` и
  `--input-dir` в импортёре; колонка «Сеть» во всех листах Excel и в CSV;
  2 новых теста (`test_import_v2_v15.py`).

### Changed
- Зафиксирован план V15: многомагазинная модель, конфиг магазинов, импорт
  Перекрёстка, качество данных (состав/БЖУ), аналитика и сравнение.
- Импорт Перекрёстка проверен на реальной выгрузке: 432 товара под `perekrestok/XSEO`,
  111 старых цен, 110 PLU пересекаются с Пятёрочкой без перезаписи.
- Пути выгрузок/фото, Referer и хосты фото в импортёре берутся из конфига сети;
  для неосновной сети создаются `catalog_<chain>_v10.xlsx/.csv/_report.json`.
- S17: сервер принимает `chain` во всех основных роутах; очередь, карточка,
  поиск, избранное, аналитика, дашборд и история цен фильтруются по сети;
  `_batch_pick_next()` выбирает товары по префиксу URL сети; `batch_record()` и
  `import_pending_details()` принимают SAP обеих сетей и пишут `chain`;
  загрузка JSON и дозагрузка фото работают по папкам сетей; 2 новых теста
  (`test_server_multi_store_v15.py`).

### Changed
- `EXPECTED_SAP` заменён на проверку «SAP разрешён для сети»; состояние пакета
  получило поле `current_chain`.
- Подмена `BASE_DIR` в тестах теперь уважается всеми путями сетей.
- S18: переключатель сети в шапке (`/api/stores`), `chain` во всех запросах UI
  (GET-параметр и POST-тело), динамические подписи/логотип, сравнение одного PLU
  между сетями (`/api/compare`); интерфейс обновлён до V15.0 без копирования `ui_v14`.
  Тест реестра и сравнения добавлен, 75 тестов зелёные.
- S19: bookmarklet'ы `pr_export_*` и `pr_batch_enrichment_v15.user.js` для
  `perekrestok.ru`: `chain='perekrestok'`, новые `source`-маркеры, SAP из
  `localStorage` с fallback `XSEO`, guard `pr-v15-*`, ссылки в интерфейсе;
  3 теста на маркеры/домены и синтаксис JS, 78 тестов зелёные.
- S20: серверное восстановление состава и описания из `details_text`, индикатор
  полноты (8 полей + источник сведений), проверка противоречий массы/объёма,
  кнопка «Повторно загрузить карточку»; одноразовая миграция `quality_repair_v15`;
  4 теста на карточке 24139, 82 теста зелёные.
- S21: `/api/search` (условия «без сахара», «белки больше N», «жиры меньше N»,
  «срок хранения больше N», «содержит …», бренд, цена), `/api/ingredients`
  с эвристиками и оговоркой про анализ текста, `/api/compare-table` с ценой за кг;
  новый раздел «Поиск по составу» в интерфейсе; 83 теста зелёные.
- S22: журнал ошибок `operation_errors`, расписание `daily_runs`, бэкап по кнопке,
  версионированный локальный API `/api/v1/*` с обязательной сетью, панель
  автоматизации в «Сборе и импортах»; 84 теста зелёные.
- `catalog_ui_server_v14.py` и `import_5ka_catalog_v9.py` применяют миграцию V10
  при старте/импорте; `ON CONFLICT` переведены на ключи с `chain`.
- `EXPECTED_SAP` берётся из конфига сети по умолчанию вместо литерала `35XY`.

## [14.0] — 2026-11-24

**Тема:** пакетное обогащение карточек через userscript и контроль качества БЖУ/галерей.

### Added
- `5ka_batch_enrichment_v14.user.js`: последовательное открытие карточек, лимит
  1–200, пауза 12–60 сек, останов при CAPTCHA, продолжение пакета.
- Восстановление БЖУ из `details_text` при обоих порядках («3.5 Белки» и «Белки 3.5»),
  игнорирование знаменателя «на 100 г/мл».
- Очистка галерей от фотографий рекомендательных блоков, отбор по `alt` и позиции.
- Одноразовый бэкап базы перед миграцией: `pyaterochka_catalog_v9.pre_v14_backup.sqlite3`.
- Возврат неполных старых карточек в очередь обогащения.
- Интерфейс: панель пакетного режима, прогресс, кнопки «Начать/Пауза/Продолжить».

### Fixed
- Сдвинутые значения БЖУ в старых снимках исправляются при старте сервера.
- Старые detail-ссылки на рекомендательные фотографии удаляются один раз.

### Known limitations
- Только одна сеть: `SAP 35XY`, домен `5ka.ru`, маркеры `source` с префиксом `5ka`.
- Detail-карточки с другим SAP отклоняются импортом.
- Состав и описание могут отсутствовать, даже если видны на странице (CD-003, CD-005).
- новая сеть требует изменений кода, а не только конфигурации.

## [9.0] — 2026-11-24

**Тема:** накопительная SQLite-база и история цен.

### Added
- `import_5ka_catalog_v9.py`: дедупликация выгрузок по SHA-256, разделение
  `captured_at` и `imported_at`, события первого появления и изменений,
  Excel (9 листов) и CSV.
- Таблицы `products`, `price_history`, `product_categories`, `exports`.

## [7.0] — 2026-11-24

**Тема:** первые DOM-only bookmarklet'ы и экспорт в Excel.

### Added
- Экспорт категорий, текущей страницы и карточки товара из видимого DOM.
- `import_5ka_exports_v7.py`, `pyaterochka_prices_v7.xlsx/.csv`.
