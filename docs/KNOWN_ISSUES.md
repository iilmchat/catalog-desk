# Реестр технических рисков Catalog Desk

**Актуально для V16.1.0 + DOM regression follow-up.** Статусы ниже сверяются с реализацией и автоматическими тестами.

## Исправления V15.1

### CD-017 — Основной импорт принимал SAP другой сети
**Статус:** Fixed. Импортёр проверяет SAP по реестру сети, однородность `chain` внутри файла и домен источника/карточки до транзакции.

### CD-018 — Userscript Перекрёстка читал состояние Пятёрочки
**Статус:** Fixed. Все обращения userscript к batch status/fail передают `chain=perekrestok`.

### CD-011 — Одно состояние пакетного сбора на всё приложение
**Статус:** Fixed. Добавлена таблица `enrichment_batch_states` с ключом сети; старое состояние переносится из V14.

### CD-019 — Миграция V9→V10 теряла внешние ключи
**Статус:** Fixed. Ограничение категорий на товар расширено до `(chain, sap_code, plu)`; после миграции выполняется `PRAGMA foreign_key_check`.

### CD-020 — Нет автоматической проверки изменений
**Статус:** Implemented. GitHub Actions запускает Python unittest, проверяет синтаксис userscript и запускает отдельный Node.js regression test для DOM-парсера Перекрёстка.

### CD-026 — Полнота данных не учитывает применимость атрибутов
**Статус:** Partially implemented in V17 foundation. Добавлены классы food / pet_food / non_food / unknown, статусы применимости и отдельные результаты извлечения. N/A исключается из знаменателя; unknown не приравнивается к N/A. Generic «Состав» для non-food сохраняется как материалы, не как пищевые ингредиенты. Метаданные хранятся обратно-совместимо в `attributes_json._catalog_meta`, без миграции существующей SQLite. Требуются реальные DOM-фикстуры non-food и Пятёрочки, а также расширение taxonomy map по наблюдаемым категориям.

## Осознанные ограничения

### CD-021 — Планирование не запускает сбор самостоятельно
**Статус:** Documented. `daily_runs` — реестр запланированных ручных DOM-выгрузок. Он не открывает браузер и не запускает сбор в фоне.

### CD-022 — Одновременная работа браузерных сборов
**Статус:** Documented. Состояния очередей независимы по сети, однако пользователю следует контролировать вкладки и профиль браузера; один userscript не должен конкурировать сам с собой за одну очередь.

### CD-023 — Автоматический анализ состава эвристический
**Статус:** Documented. Поиск ингредиентов и маркеров основан на тексте состава, не является лабораторной проверкой или медицинской оценкой.

### CD-024 — Неполное извлечение деталей карточки Перекрёстка
**Статус:** Partially mitigated / source limitation confirmed. Реальная DOM-фикстура PLU 4406119 / SAP XSEO добавлена. Userscript теперь ограничивает текст и поиск изображений узлом `[data-qa="product-screen"]`, а характеристики извлекает из `[data-qa="product-detail-attribute"]`; это исключает соседние рекомендации. Фикстура подтверждает название, бренд, цену 369.99 RUB, изображения, БЖУ и атрибуты. В этой сохранённой странице нет состава и отдельного фактического описания: отсутствие этих значений не является ошибкой парсера. Нужны дополнительные фикстуры страниц, где состав/описание реально присутствуют или свёрнуты; поэтому issue не закрыта полностью.

### CD-025 — Нет DOM-регрессии userscript
**Статус:** Partially implemented. Добавлены реальная HTML-фикстура Перекрёстка, Python-тесты структуры/полей/границ секций и Node.js-тесты helper-функций парсера в CI. Покрытие Пятёрочки и браузерного DOM-runtime ещё отсутствует; issue остаётся открытой до добавления второй сети и end-to-end проверки сборки payload.

## Продуктовые задачи следующего этапа

- Полнота и свежесть данных, повторное обогащение.
- Углублённая аналитика цен и повторяющихся акций.
- Справочник ингредиентов и история изменения состава.
- Мониторинг ассортимента и качества фотографий.
- Надёжное локальное расписание с понятным режимом выполнения.
