# Changelog

Все значимые изменения проекта фиксируются в этом файле.
Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [Semantic Versioning](https://semver.org/lang/ru/).

## [Unreleased]

### Added
- Реальная DOM-фикстура карточки Перекрёстка PLU 4406119 и regression tests для названия, бренда, цены, изображений, БЖУ, атрибутов, отсутствующего состава и исключения рекомендаций.
- Node.js regression test helper-функций userscript Перекрёстка; тест запускается в GitHub Actions.

### Changed
- Userscript Перекрёстка предпочитает `[data-qa="product-screen"]` как корень товара; рекомендации и карусели за пределами этого узла не попадают в `details_text` и поиск изображений.
- Атрибуты карточки извлекаются из повторяющихся `[data-qa="product-detail-attribute"]`; скрытая SEO meta description не используется как фактическое описание товара.

### Verified
- После релиза V16.1.0 проверено одиночное обновление одной карточки Пятёрочки (PLU 4275044, SAP 35XY) и одной карточки Перекрёстка (PLU 4406119, SAP XSEO): запись деталей и снимка истории созданы; массовые очереди и batch-state не затронуты.
- Сохранённая карточка Перекрёстка содержит название, бренд, цену 369.99 RUB, три image nodes, nutrition (52.7 kcal, proteins 1.2 g, fats 0.3 g, carbs 11.2 g) и 11 характеристик.
- В HTML-фикстуре отсутствуют состав и отдельное фактическое описание; SEO meta description повторяет маркетинговый заголовок и намеренно не считается описанием.
- Локальная регрессия до этого follow-up: 100 Python-тестов прошли; синтаксис четырёх userscript проверен Node.js; SHA-256 рабочей SQLite-базы до/после тестов совпал.

### Remaining
- CD-024 частично подтверждён: состав/описание не представлены в этой карточке; для полного закрытия нужны фикстуры страниц, где эти секции реально доступны/свёрнуты.
- CD-025 частично реализован для Перекрёстка; требуется DOM-покрытие Пятёрочки и интеграционная проверка формирования payload.

## [V16.1.0] — 2026-11-26

### Added
- В массовой очереди показывается распределение карточек по полноте: 100%, 80%, 60%, 40%, 20% и 0%.
- Карточку товара можно открыть нажатием на её строку или название в массовой очереди.

### Changed
- Сводные показатели «Обработано», «Ожидают» и общий прогресс рассчитываются по фактическому наличию записи в `product_details`; статусы действий очереди остаются отдельными.

## [V16.0.0] — 2026-11-26

### Added
- Одиночное обновление сведений из карточки товара по одноразовому токену, привязанному к `chain + SAP + PLU`.
- Отдельный импорт одного снимка в `product_details`, историю деталей, журнал импортов и галерею; массовая очередь и batch-состояние не меняются.
- Userscript V16 для обеих сетей: одиночный режим и прежний пакетный режим с чтением только видимого DOM.

### Fixed
- Прогресс категорий рассчитывается по наличию записи `product_details`, а не по статусу задачи массовой очереди.
- Файлы одиночных снимков хранятся в подпапке `_single_refresh`, не попадающей в общий импорт JSON.

## [V15.1.0] — 2026-11-25

### Fixed
- Основной импорт отклоняет неверный SAP, смешанные сети и URL, принадлежащий другой сети.
- Userscript Перекрёстка адресует batch status/fail явно к `chain=perekrestok`; состояние пакетной обработки разделено по сетям.
- Существующее пакетное состояние V14 переносится в новую таблицу без потери текущей карточки.
- Миграция V9→V10 сохраняет составной внешний ключ `(chain, sap_code, plu)` и проверяет `PRAGMA foreign_key_check`.

### Changed
- Планировщик обозначен как реестр ручных DOM-выгрузок; он не запускает браузер или сбор автоматически.
- Добавлены тесты изоляции очередей, валидации SAP/доменов и внешних ключей.
- Добавлен GitHub Actions CI для Python-тестов и синтаксиса userscript.

### Added
- (записи добавляются в каждом коммите с кодом)

## [V15.0] — 2026-11-25

**Тема:** Catalog Desk становится многомагазинной системой: Пятёрочка + Перекрёсток в одной базе с историей, качеством данных и локальным API.

### Added
- Документация по образцу PriceScope: `README.md`, `GET_STARTED.md`, `TODO.md`, `docs/` (хаб, реестр `CD-XXX`, TODO_KI, TODO_SPRINTS, RULES, ARCHITECTURE, RELEASES, ADR, дизайн V15, пользовательское руководство и QA-чеклист).
- Git-репозиторий: `.gitignore`, `.gitattributes`, `.editorconfig` — код и документация версионируются, база/выгрузки/фотографии исключены.
- S15: `catalog_config.py` — реестр сетей `5ka`/`perekrestok` (домены, префиксы URL, хосты фото, SAP, `source`-маркеры, пути); `catalog_migrations.py` — миграция V9→V10 с добавлением `chain`, расширением ключей и одноразовым бэкапом; 6 новых тестов (`test_catalog_config_v15.py`).

### Added
- S16: контракт Export v2 (`schema_version=2`, `chain`) с чтением v1; сеть определяется по явному полю, затем по домену URL, затем по маркеру `source`; `--chain` и `--input-dir` в импортёре; колонка «Сеть» во всех листах Excel и в CSV; 2 новых теста (`test_import_v2_v15.py`).

### Changed
- S17–S22: multi-store сервер, сборщики Перекрёстка, качество данных, поиск/сравнение, история карточки, журнал ошибок, ручное расписание и локальный API v1. Подробности — в истории соответствующих релизов и документации.

## [14.0] — 2026-11-24

**Тема:** пакетное обогащение карточек через userscript и контроль качества БЖУ/галерей.

### Added
- `5ka_batch_enrichment_v14.user.js`: последовательное открытие карточек, лимит 1–200, пауза 12–60 сек, останов при CAPTCHA, продолжение пакета.
- Восстановление БЖУ из `details_text` при обоих порядках («3.5 Белки» и «Белки 3.5»), игнорирование знаменателя «на 100 г/мл».
- Очистка галерей от фотографий рекомендательных блоков, отбор по `alt` и позиции.
- Одноразовый бэкап базы перед миграцией: `pyaterochka_catalog_v9.pre_v14_backup.sqlite3`.

### Fixed
- Сдвинутые значения БЖУ в старых снимках исправляются при старте сервера.
- Старые detail-ссылки на рекомендательные фотографии удаляются один раз.

### Known limitations
- Только одна сеть: `SAP 35XY`, домен `5ka.ru`, маркеры `source` с префиксом `5ka`.
- Detail-карточки с другим SAP отклоняются импортом.
- Состав и описание могут отсутствовать, даже если видны на странице (CD-003, CD-005).
- новая сеть требует изменений кода, а не только конфигурации.

## [9.0] — 2026-11-24

**Тема:** накопительная SQLite-база и история цен.

- `import_5ka_catalog_v9.py`: дедупликация выгрузок по SHA-256, разделение `captured_at` и `imported_at`, события первого появления и изменений; Excel и CSV.

## [7.0] — 2026-11-24

**Тема:** первые DOM-only bookmarklet'ы и экспорт в Excel.

### Added
- Экспорт категорий, текущей страницы и карточки товара из видимого DOM.
- `import_5ka_exports_v7.py`, `pyaterochka_prices_v7.xlsx/.csv`.
